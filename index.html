How I work

Verify on a live system first, then promote into the shared template.
  • Evidence over inference. Fixes are proven against a running cluster before being generalized into provisioning templates — along with the automated check that keeps them proven.
  • Distrust silent success. A recurring contribution is finding code paths that log success while quietly discarding the change. Several of the highest-impact bugs I have fixed reported no error at all.
  • Risk-sequenced delivery. Commits split by blast radius; dev before UAT before production; explicit sign-off ahead of production mutations.
  • GitOps over live mutation. Infrastructure changes flow through version control and reconciliation, not ad-hoc commands.
